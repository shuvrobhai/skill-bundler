## Summary
The specification provides an excellent architectural roadmap for hardening the skill bundler contract, centralizing constants, and typed exceptions. However, the proposed regex-based splitting combined with Structure Map validation introduces a destructive bug if false positives occur, and the regex itself is not cross-platform safe. There are also a few gaps in path sanitization and backward compatibility that need addressing before implementation.

## Blockers
### 🔴 Destructive fragmentation via regex split, `docs/specs/0002-architecture-and-contract-corrections.md:36`
**Problem**: The spec relies on "line anchored marker splitting" combined with Structure Map validation to prevent delimiter collisions. If `re.split` or similar naive splitting is used, a spurious marker inside a code block will cause the text to be split and the delimiter string to be consumed (removed) from the resulting content, even if the Structure Map validation later rejects it as a false positive.
**Why it matters**: Valid code files containing the marker string at the start of a line will be irreversibly corrupted during unpacking, with the marker removed and the file fragmented.
**Suggested fix**: Specify the use of a non-destructive sequential parser (e.g., `re.finditer`) so that if a marker is rejected by Structure Map validation, it remains intact as normal text within the enclosing file section.

## Major
### 🟠 Regex anchor fails on CRLF line endings, `docs/specs/0002-architecture-and-contract-corrections.md:36`
**Problem**: The specified regex `(?m)^<!-- SOURCE:\s*(.*?)\s*-->$` uses the `$` anchor. In Python, `$` matches immediately before a newline (`\n`). On files with Windows CRLF (`\r\n`) endings, the character before `\n` is `\r`, which does not match `>`.
**Why it matters**: Unpacking will silently fail to find any file boundaries on bundles saved on Windows or checked out with `core.autocrlf=true`, breaking cross-platform compatibility and backward compatibility with old bundles.
**Suggested fix**: Update the regex to optionally allow a carriage return before the end of the line: `(?m)^<!-- SOURCE:\s*(.*?)\s*-->\r?$`.

## Minor
### 🟡 Incomplete title sanitization for hidden directories, `docs/specs/0002-architecture-and-contract-corrections.md:38`
**Problem**: AC-7 sanitizes dot-only (`.`) and parent (`..`) strings. However, it does not explicitly prevent titles like `.git` or `.ssh`.
**Why it matters**: Unpacking a bundle titled `.git` could overwrite the user's local repository index or configuration if unpacked in a repo root.
**Suggested fix**: Enhance AC-7 to also reject titles that start with a dot (hidden directories), falling back to `unpacked-skill`.

### 🟡 Missing Structure Map parser in Build Plan, `docs/specs/0002-architecture-and-contract-corrections.md:121`
**Problem**: The spec mandates that in-band delimiters be "validated against the bundle's Structure Map", but there is no requirement or build task to implement a parser that can read the Structure Map from the bundle text.
**Why it matters**: The validation step cannot be implemented without a parser to extract valid paths from the preamble.
**Suggested fix**: Add a build task to implement a Structure Map parser in `unpacker.py`.

### 🟡 Missing backward compatibility alias for `parse_skill`, `docs/specs/0002-architecture-and-contract-corrections.md:118`
**Problem**: The spec moves frontmatter parsing to `frontmatter.py` but relies on `__init__.py` for backward compatibility. External scripts might import `parse_skill` directly from `skill_bundler.bundler`.
**Why it matters**: Moving the function without leaving a direct alias in `bundler.py` is a breaking change for scripts bypassing `__init__.py`.
**Suggested fix**: Explicitly specify leaving a public alias (e.g., `parse_skill = frontmatter.parse_skill`) in `bundler.py`.

## Strengths
- Centralizing markers into `constants.py` is a very robust design choice that will eliminate the drift vulnerabilities seen in the current implementation.
- The shift from direct `sys.exit` to typed exceptions like `ClipboardError` drastically improves the library's embeddability and testability.

## Test coverage
The spec's AC-11 mandates comprehensive edge case coverage (extra frontmatter rules, multiline descriptions, marker collisions, path traversal, headless clipboard, and dogfooding), which perfectly addresses the missing test coverage for the discovered vulnerabilities.
